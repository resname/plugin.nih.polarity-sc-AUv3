# Polarity-SC-Dark → AUv3: Design

Date: 2026-10-21
Repo: https://github.com/resname/plugin.nih.polarity-sc-AUv3 (fork of polarity/plugin.nih.polarity-sc-dark)

## Intent and why

The plugin (a Rust/nih-plug fork of Spectral Compressor: STFT spectral
compressor with FFT-bin compressors, sidechain input, threshold-curve
matching, Vizia GUI) should be loadable in AU-only hosts: Logic Pro,
GarageBand, MainStage, Digital Performer, Luna, and — later — iPad.
The chosen format is **AUv3 only** (user explicitly prefers AUv3 over
AUv2 for stability).

## Goals

- Load, validate (`auval`), and run the plugin as a macOS AUv3 in Logic Pro.
- Keep all existing behavior: 47 parameters, sidechain aux input, bypass,
  sample-accurate automation, latency reporting, curve presets, IR export.
- Keep the existing Vizia GUI working unchanged.
- Keep the existing CLAP and VST3 outputs intact (CLAP/VST3 are the only
  formats Cubase supports; AUv3 must be an *additional* target, not a
  replacement).

## Non-goals / anti-goals

- No iOS/iPad AUv3 in this pass (deferred; see open risks).
- No rewrite of DSP or GUI. A "whole plugin rewrite" that discards working
  Rust DSP + Vizia is an anti-goal: research showed it costs 2–4 months
  (JUCE/iPlug2 port) with zero behavioral gain.
- No AUv2 output.

## Research findings that shaped this (Oct 2026)

- nih-plug has no AU target and the upstream author declined AUv3
  (robbert-vdh/nih-plug#63); nih-plug is in maintenance mode.
- free-audio/clap-wrapper (MIT) adds CLAP→AUv3 for macOS since v0.15.1
  (Jul 2025): builds a `.appex` with Xcode, wraps the plugin's CLAP,
  translates params/state/presets, and creates the CLAP GUI's Cocoa view
  inside an `AUAudioUnitFactory`/`NSViewController`
  (`auv3_audiounit.mm`). nih-plug's CLAP wrapper supports
  `CLAP_WINDOW_API_COCOA` (gui_set_parent), so the Vizia window parents
  into the AUv3 view unmodified.
- Hand-rolled Rust-staticlib + cbindgen + ObjC++ `AUAudioUnit` shell is a
  proven fallback pattern (timboudreau/audio_unit_rust_demo,
  truce-audio/truce, helpermedia/beamer).
- JUCE/iPlug2 ports cost 2–4 months, discard Rust + Vizia, and buy nothing
  behaviorally.
- Host facts: Cubase hosts no AU format at all. Logic AUv3 audio
  sidechains are buggy (Logic ignores declared AUv3 bus layouts — JUCE
  forum reports); this risk exists for *every* AUv3 path.
- Building/signing the `.appex` requires macOS + full Xcode + Developer ID
  signing (ad-hoc signing is rejected at `pluginkit` registration).
  Notarization for distribution. All Rust/Linux-side work stays here.

## Constraints

- GPL-3.0 repo (fork of nih-plug GPLv3 VST3 bindings); clap-wrapper is
  MIT — license-compatible, no changes to our licensing needed.
- This dev box is Linux. Rust builds, tests, FFI glue: done here. macOS
  runner (real Mac or GHA `macos-15`) required for Xcode build, signing,
  notarization, `auval`, Logic smoke test.
- The user has a GitHub account `resname` with a fork; Apple signing
  identity availability must be checked at implementation time.

## The core decision (user opted out of further questions; this is my call)

**Primary path: clap-wrapper CLAP→AUv3 prototype, gated on a Logic
sidechain test.**

1. Prototype (days): CMake super-project wrapping the nih-plug-built CLAP
   binary with clap-wrapper, `-DCLAP_WRAPPER_BUILD_AUV3=ON`, Xcode
   generator on a macOS machine. Existing `.clap` from
   `cargo xtask bundle` is the input; no DSP/GUI changes.
2. **Gate (early, before polishing):** install in Logic Pro; test audio
   sidechain routing specifically. If Logic won't feed the aux bus, stop
   and re-decide (see fallback ladder).
3. If the prototype holds: wire CI (Linux Rust build → macOS runner
   CMake/Xcode + sign + `auval`), document install steps, done.

**Fallback ladder** (each rung only if the previous fails Logic testing):
1. Hand-rolled ObjC++ `AUAudioUnit` appex around a Rust staticlib
   (cbindgen C ABI; timboudreau demo + truce as templates; ~2.5 weeks
   shell + plumbing, plus GUI work — Vizia-NSView experiment first,
   SwiftUI rebuild second). Proven at small scale; also the path that
   unlocks iOS later. **This is the pre-approved rung:** the user
   explicitly rejected AUv2, and preserving the later-iPad path favors it.
2. clap-wrapper AUv2 `.component` — only with fresh explicit user blessing
   (contradicts their stated AUv3 preference; also closes the iOS path).
3. Not pursued: JUCE or iPlug2 full rewrite (rejected: month-scale effort,
   lost Vizia/GUI work, $800+/per-seat or AGPL licensing, no gain).

## Settled calls (design review, 2026-10-21)

- Fallback on Logic-sidechain gate failure: hand-rolled ObjC++ AUv3
  (ladder rung 1), not AUv2.
- Validation scope this pass: Logic Pro only.
- Distribution: user only; notarization and public install docs deferred.
- CI signing automation: deferred behind the prototype; Apple
  membership/certificate availability is a user-side fact.

## Acceptance

- `auval -v aufx PscD Plsc` (manufacturer `polarity-music`) passes.
- Plugin appears in Logic Pro AU list, loads, processes stereo, sidechain
  input receives audio from another Logic track, GUI opens and renders.
- Existing `cargo xtask bundle polarity_sc_dark` CLAP/VST3 outputs
  unchanged on Linux.

## Open risks (surfaced, not solved)

- Logic-side AUv3 sidechain may be broken at the host level → the gate is
  real; fallback ladder exists.
- clap-wrapper AUv3 is young (one release cycle); known issues: Ableton
  Live AUv3 scan segfault (#514), iOS appex bootstrap race (#553).
- Vizia-on-macOS via baseview/cocoa is used by the project but has little
  CI evidence; first Logic GUI test may surface mac-only Vizia bugs.
- Out-of-process AUv3: Logic loads appexes out-of-process; Vizia hot-reload
  feature and any dev-only deps must not be in release builds.

## Left to the builder

- Exact clap-wrapper version pin and CMake recipe.
- Manufacturer/subtype fourccs, Info.plist tags, bundle naming.
- CI runner setup and signing/notarization automation.
- Everything in the fallback ladder unless triggered.
